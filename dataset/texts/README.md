# Texts

One file per `text_id`: the words the aligner is told were spoken. Everything
downstream — word indices, the envelope, every timestamp — rests on these files
being right, so they are worth more care than anything else in the dataset.

```
texts/<text_id>.json        verbatim (aligner input), display (punctuated), gap_labels
texts/overrides/<file_id>.txt   one reading's own words, when it deviates
```

`scripts/align_clean.py` resolves a transcript in this order, first hit wins:

1. `overrides/<file_id>.txt`
2. `<text_id>.json` → `verbatim`
3. `<text_id>.txt`

## Fields

| Field | Meaning |
|---|---|
| `verbatim` | One line, the words as delivered. `rostrum.align.mfa.normalise_for_alignment` lowercases it, expands numerals and strips punctuation to build the `.lab`. |
| `display` | The punctuated, paragraphed version. Punctuation is what `rostrum.text` turns into `boundary` / `minor` / `none` gap expectations (spec 7.1). |
| `gap_labels` | Generated by `rostrum.text`, never hand-written. `null` until then. |

A token-count mismatch between `verbatim` and the aligned TextGrid is a hard
error in `read_textgrid`, by design: it means word index *i* no longer refers to
the same word across renditions, which would invalidate every comparison.

That tail sits inside the audio the false-alarm rate is measured over and inside

`excerpt_end_s` per file in `SOURCES.yaml`, then
`python scripts/build_clean.py --force`, then re-aligning and re-injecting — the
labels are derived from time maps over the parent, so they do not survive a
re-cut of the parent.

**Only 9 of 62 clean readings are aligned.** The 9 are the injection parents

label record but no `TextGrid`, so they cannot contribute per-word statistics to
their text's envelope — which is the one thing 62 readings were collected for.
`make align` over the remaining 53 is the highest-value outstanding data task.

## Two things the LibriVox readings need before they will align

An ASR probe (`faster-whisper tiny.en`, 2026-10-05) over the head and tail of
the built clean WAVs found:

1. **Spoken intros and outros that are not part of the text.**
   `s1_lv16` opens *"This is a LibriVox recording. All LibriVox recordings are
   in the public domain…"*; `s1_lv01` opens *"The Gettysburg Address by Abraham
   Lincoln read for LibriVox.org by Ann Boulais"* and closes *"End of the
   Gettysburg Address. This recording is in the public domain."*
   → set `excerpt_start_s` / `excerpt_end_s` per file in `SOURCES.yaml`, then
   `python scripts/build_clean.py --force`.

2. **Readers who deviate from the Bliss copy.** `s1_lv01` was heard reading
   *"…a new nation, conceived in liberty and dedicated to the proposition…"* and
   ending *"…shall not perish from this earth"*, where `s1_lv16` ends *"…from
   the earth"*.
   → give any such reading its own `overrides/<file_id>.txt`.

Both show up as flagged files in `scripts/align_report.py` (unaligned-word
fraction above `paths.mfa.qc.max_unaligned_frac`), so the report is the list of
files still needing one of these two fixes.

> Note for the envelope (spec 10.1): a reading with its own override has a
> *different* word sequence from the library text, so word *i* is not comparable
> across the two. Decide per text whether to normalise the readings to one
> edition (drop the deviating takes) or to align word sequences across renditions
> first. This is a design decision, not a bug in the aligner.
