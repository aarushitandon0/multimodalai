# Rostrum Contrastive Delivery Dataset — datasheet

Paired recordings in which the **same text** is delivered well by several
skilled speakers and mirrored by a **graded spectrum of flawed deliveries**,
with exact, machine-generated flaw timestamps.

Datasheet structure follows Gebru et al., *Datasheets for Datasets*. Every
count, table and QC number below is regenerated by
[`../scripts/package_dataset.py`](../scripts/package_dataset.py) from the files
actually on disk — the blocks marked `generated` are never edited by hand, so a
stale number here is a bug, not a typo.

> **Build status.** The numbers below describe this checkout. Where a table says
> a stage has not run, the corresponding audio is simply not built yet; see
> [Known limitations](#known-limitations).

---

## Motivation

**What gap does this fill?** Standard speech corpora label *what* was said.
None maps skilled rhetorical delivery against a spectrum of degraded deliveries
**of the exact same text**. Without that pairing, a delivery-evaluation system
cannot separate three confounded causes of an acoustic deviation: the wording,
the speaker's voice, and the delivery itself.

Holding the text fixed removes the first. Comparing word *i* to word *i* across
several readings, in speaker-normalised units (semitones re speaker median,
energy z-scored per recording), removes most of the second. What is left is
delivery, and it is what Rostrum scores.

**Who created it?** The Rostrum project team, for the Multimodal AI hackathon
(Track C). The sourced audio is public-domain material; the flawed material is
generated by this repository's injection engine and recorded by the team.

**Who funded it?** No external funding.

Each instance is **one audio file** (16 kHz mono 16-bit PCM WAV) with a
transcript, a forced alignment, and — where it is not a clean reading — a label
JSON giving every flaw's span, type and severity.

**Tiers.**

| Tier | Meaning | Example |
|---|---|---|
| **Gold** | The original orator's own recording | FDR's *Day of Infamy* address; JFK's inaugural (JFK Library) |
| **Silver** | Several skilled public-domain readings of one text | LibriVox's 150th-anniversary Gettysburg collection (16 readers) |
| **Bronze** | Team recordings, matched microphone and room | clean take + deliberate flawed takes per speaker |

**Texts.** Short, well-known public-domain speeches, 60–150 s of audio each.
`texts/<text_id>.json` carries the `verbatim` form (the aligner's input) and the
`display` form (punctuation and paragraphing, which is what the gap labels
`boundary` / `minor` / `none` are derived from).

### Labels

Eight flaw labels in six rubric categories, on a five-step severity ladder
(L0 0.00 · L1 0.15 · L2 0.35 · L3 0.60 · L4 0.90):

| Category | Labels |
|---|---|
| Pace | `rushing`, `dragging` |
| Pausing | `missing_pause`, `hesitation_pause` |
| Intonation | `monotone` |
| Emphasis | `misplaced_stress` |
| Energy | `low_energy` / `fading` |
| Clarity | `mumbling` — **human-recorded only** |

`mumbling` is never synthesised: a low-pass filter models a bad microphone, not

## Collection process

1. **Sources are declared before anything is downloaded.** Each entry in
   [`SOURCES.yaml`](SOURCES.yaml) names the page the licence is stated on, the
   licence text itself, the per-file reader credit and a provenance artefact
   (an HTML capture or PDF) stored under [`provenance/`](provenance/) — see
   [`provenance/CAPTURE_LOG.md`](provenance/CAPTURE_LOG.md) for when each was
   captured. `scripts/download_sources.py` refuses to fetch a source whose
   licence does not permit modification and redistribution.
2. **A licence row is written per file** into [`LICENSES.csv`](LICENSES.csv),
   with the source URL, retrieval date and the SHA-256 of the file retrieved.
3. **Team recordings** (Bronze) are made on one microphone in one room, with a
   clean take and deliberately flawed takes per speaker, under the written
   consent recorded in [`CONSENT.md`](CONSENT.md). Mixed genders are recruited
   on purpose: the speaker-agnostic claim cannot be tested on one voice type.

## Preprocessing

Identical for every file, sourced or recorded
([`../configs/features.yaml`](../configs/features.yaml) `audio:`):

- decode → **16 kHz, mono, float32** internally, 16-bit PCM WAV on disk;
- trim leading/trailing silence to **300 ms**;
- loudness-normalise to **−23 LUFS** integrated, peak limited to **≤ −1 dBFS**;
- per-file QC row in [`qc/clean_build.csv`](qc/clean_build.csv): both digests,
  measured LUFS, peak, duration.

All timestamps anywhere in the dataset are **seconds, float, 3 decimals,
relative to the start of the processed WAV** — never the original download.

Forced alignment is **Montreal Forced Aligner** (`english_us_arpa` acoustic
model and dictionary), run in its own conda environment, producing word and
phone tiers in `alignments/*.TextGrid`. `faster-whisper` is used only to check
ASR-vs-transcript WER; a file above 0.25 WER is rejected rather than aligned.

## Labelling

### Injected files (`audio/injected/`)

Labels are **derived, not annotated**. Each edit is applied at word boundaries
only, with 10 ms raised-cosine crossfades, and returns an exact old → new time
map; the label spans are read off that map, so a span cannot drift from the
audio it describes. Inserted silence is looped room tone taken from the
recording's own pauses, never digital zeros. Time-stretching is TD-PSOLA via
Praat; no vocoder is used.

Every injected file then passes two gates before it is kept:

- **Re-alignment.** The edited file is force-aligned again; if any word boundary
  moved more than **50 ms** from its predicted position, the file is rejected.
- **UTMOS.** An L1 file that loses more than **0.3 MOS** against its clean
  parent is an artefact, not a near-perfect delivery, and is rejected.

Rejections are recorded with their reason in
[`qc/rejections.csv`](qc/rejections.csv) and the file is deleted. Quality over
quantity. One row is one *attempt*, so a `file_id` there may still ship: the
engine re-draws the span and retries, and the `final_status` column says which
happened (`retried_ok` 114 rows, `dropped` 66). **Neither gate has been run
over this build** — see [`qc/README.md`](qc/README.md).

### Human files (`audio/human_flawed/`)

**Empty: nothing has been recorded.** The protocol, once there are files, is
hand-labelling in Praat following
[`ANNOTATION_GUIDE.md`](ANNOTATION_GUIDE.md), which fixes one audio example per
label. **30%** of files are double-annotated; agreement is reported as event-F1
at a **200 ms collar** plus Cohen's κ on the label of matched events, in
`qc/agreement.md`. See [`audio/human_flawed/README.md`](audio/human_flawed/README.md)
for what the absence costs.

## Splits

**Leave-one-text-out (LOTO) cross-validation**, one fold per text, written to
[`splits/loto.json`](splits/loto.json). Every threshold, weight, `k_c` and the
flaw classifier is fit on the *other* texts and evaluated on the held-out one;
results are reported as mean ± sd across folds. With a handful of texts a single
fixed split would be fragile.

Two rules are enforced by the builder (`rostrum.data.splits`), not by
convention:

1. nothing from the held-out text reaches the training side of its fold;
2. **human flawed takes are test-only** — they never calibrate anything, in any
   fold, so no synthetic artefact can be learned and then credited on real
   speech.

`MANIFEST.csv`'s `split_fold` column records, for each file, the one fold it is
tested in.

## Licences and consent

Per-file licensing is recorded in [`LICENSES.csv`](LICENSES.csv) with a source
URL and retrieval date. Because Rostrum publishes *modified* audio, every source
must permit **both modification and redistribution**, so only public domain, CC0
and CC BY material is admissible. This is why TED talks (CC BY-NC-ND) are
excluded, along with YouTube rips and any voice cloning of real people.

LibriVox recordings are public domain in the USA; the exact wording LibriVox
states, including its own caveat about other jurisdictions, is reproduced
verbatim in the `licence` column rather than paraphrased.

Team recordings are released CC BY 4.0 under the recorded consent in
[`CONSENT.md`](CONSENT.md): speakers consented to publication of the audio and
of edited versions of it, and may withdraw, in which case their files and rows
are deleted and the checksums regenerated.

`scripts/check_provenance.py` fails the build if any shipped audio file lacks a
licence row, a permissive licence, or a provenance artefact. It runs in CI.

## Intended uses

- **Intended.** Research and teaching on delivery analysis: building per-text
  prosodic envelopes, detecting and *temporally grounding* delivery flaws,
  evaluating rubric scoring, and benchmarking sound-event-detection metrics on
  prosodic events.
- **Out of scope.** Speaker verification or identification; emotion recognition;
  ASR training (16 kHz, loudness-normalised, a handful of texts); any
  high-stakes assessment of a person. The flaw labels describe *a reading of one
  text*, not a speaker's ability.
- **Prohibited.** Voice cloning or synthesis of the identifiable speakers in
  this dataset, and any use that presents a score from it as a measure of
  someone's competence or employability.

## Known limitations

- **Invariant-9 QC has not been run.** All 266 injected label JSONs carry
  `"qc": null`, and `qc/realign.csv` and `qc/utmos.csv` hold headers only. The
  re-alignment gate (reject if any word boundary moved > 50 ms) and the UTMOS
  gate (reject L1 if the score drops > 0.3) are implemented in
  `rostrum.inject.qc` and wired into `scripts/qc_dataset.py`, but they need the
  MFA conda env, so they run in the Docker image and have not run over this
  build. `label_passed` returns `False` for an unverified label on purpose:
  treat every injected span as *unverified*, not as verified-and-passed.
- **Clean readings are not trimmed to the text.** `excerpt_end_s` is unset for
  61 of 62 clean files, so most carry the spoken LibriVox outro after the last
  word of the text: 10.5 s on `s1_lv01`, 12.5 s on `s5_lv01`, 12.2 s on
  `s7_lv01`, measured as duration minus the last aligned word offset. That
  audio is inside the file the false-alarm rate is measured over and inside the
  envelope's pause statistics, and it is not part of any transcript. Trimming it
  means re-running `scripts/build_clean.py --force`, re-aligning and
  re-injecting. See `texts/README.md`.
- **The `s3_fdr_infamy` excerpt contains applause.** Roughly 55 s of the 413 s
  gold recording is applause, in four spans, louder than the speech around it.
  Flaw spans were placed across the whole file, so some `s3_fdr_gold_*` labels
  fall in applause rather than in delivery. Re-cut to ~257 s or mask the spans
  before trusting this text's numbers.
- **The label grid is not square.** 66 injection attempts never produced a file
  (`qc/rejections.csv`, `final_status = dropped`): 48 of them `monotone`, whose
  spans kept landing on unvoiced or too-short regions, which is why `monotone`
  ships 20 files where the other labels ship 32–36. `misplaced_stress` and
  `missing_pause` lost a few the same way.
- **No human-recorded takes.** `audio/human_flawed/` is empty, so `mumbling`
  and the whole Clarity category have no ground truth, the test-only rule in
  invariant 11 is untested, and the male/female score-gap check cannot be run.
- **Channel differences.** Clean readings come from different recordings with
  different microphones and rooms. Spectral, MFCC and voice-quality features are
  therefore **only ever compared within one channel** (a clean file against its
  own edit, or a speaker's clean take against their own flawed take) — they can
  distinguish `mumbling` but never trigger a flaw against the multi-speaker
  envelope. Timing, pauses, rate, semitone F0, relative energy and prominence
  are the channel-robust features the envelope is built from.
- **Synthetic artefacts.** Programmatic injection cannot produce every real
  flaw. PSOLA stretching and room-tone insertion leave traces a model might
  learn instead of the prosody; this is exactly why human takes are test-only
  and why synthetic and human results are reported separately.
- **Few texts.** Envelope statistics rest on few references per word, so the
  median and MAD are noisy; the leave-one-reference-out confidence band exists
  to make that visible rather than hide it. LOTO over a handful of texts also
  means fold-to-fold variance is large — hence mean ± sd, never a single number.
- **English only, read delivery only.** Declamation of memorised or read text,
  North-American English, no spontaneous speech, no other languages.
- **Reader skill is assumed, not verified.** LibriVox readers are volunteers;
  "skilled" means "fluent and intentional", not "professional". A reading that
  is itself flawed widens the envelope and makes detection *more* conservative.
- **Severity is a parameter, not a perception.** L1–L4 are defined by edit
  magnitude. A listener study calibrating them against perceived severity has
  not been run.

## Maintenance and mirror

The dataset is rebuilt end to end by `make data`, and packaged by
`python scripts/package_dataset.py`, which regenerates `MANIFEST.csv`,
`splits/loto.json`, this datasheet's generated blocks, `checksums.sha256`, the
`dataset_sample/` subset and `dist/rostrum_dataset_v1.zip`.

Audio is hosted off-GitHub where it exceeds the repository size limit.
**Mirror link: TODO(verify)** — fill in once the public mirror (Hugging Face
Dataset or Google Drive) is published, and link it from the top-level README.
The repository always carries `dataset_sample/` — 33 files, 45 MB — so the demo
runs without the download. The sample is chosen to be *contrastive*, not merely
small: one injected file for each of the 30 label x level combinations that
exist, **plus the clean reading each one was cut from**, because a flawed file
on its own shows nothing. Representatives are taken from the shortest texts
(`s5_im_nobody`, `s7_sonnet18`) so the full grid fits in the budget. Its
`labels/`, `alignments/` and `transcripts/` directories are populated for every
file in it.

`dataset/labels/` and `dataset/alignments/` are tracked in git for the whole
328-file corpus — they are 25 MB of text and they are the part of the
deliverable the brief names explicitly ("transcripts, and alignment labels").
Only the WAVs live behind the mirror.

Verify a download with:

```bash
cd dataset && sha256sum -c checksums.sha256
```
